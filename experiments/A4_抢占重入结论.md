# A4 抢占重入验证结论

- 日期：2026-10-12　分支：V1 / main　设备：RTX 4060 8G　模型：Qwen3-0.6B
- 脚本：`a_preempt.py`（采集）/ `a4_compare.py`（比对）
- 数据：`results/a4_V1b_{ctl,ctl2,n23,px}.json`、`results/a4_mainb_{ctl,n23,px}.json`、`results/a4_V1_{ctl,ctl2,n15,px}.json`
- 比对存档：`results/a4_compare_{V1b,mainb}_n23.txt`、`results/a4_cross_impl.txt`

## 结论

**P4（抢占重入）未发现缺陷。** V1 与 main 在同一抢占压力下判定均为 PASS。

| 判据 | V1 | main |
| :--- | :--- | :--- |
| L1 功能健全（全部完成 / 长度正确 / 输出非空） | PASS（24/24，9 次抢占） | PASS（24/24，10 次抢占） |
| L1' 结构不变式（块覆盖 / `num_cached_tokens` 上界） | PASS（24768 点全 0 违反） | PASS（24768 点全 0 违反） |
| L2 数值层等价（对比**各自分支**实测的噪声地板） | PASS（1.24×，地板 5.88e-2） | PASS（1.12×，地板 5.10e-2） |
| **L3 无 KV 污染特征** | **PASS（8 条被抢占 seq，0 条首异位置落在抢占点）** | **PASS（9 条，0 条）** |
| 跨实现（V1 vs main） | 无抢占基准 Δ = 5.29e-2；抢占组 Δ = 5.53e-2 → **1.05×** | 同 |

## 关键证据

### 1. 抢占重入后输出与"从不抢占"一致

高压力场景（N=24，plen=768，O∈[240,792]，强制池 72 = admit 所需，需求 132 块 → 必然抢占）。

V1 的 9 次抢占落在 8 条 seq 上；main 的 10 次落在 9 条上：

| 情况 | V1 | main | 含义 |
| :--- | ---: | ---: | :--- |
| 输出与对照**完全一致** | 1 | 4 | 重入后全部 token 相同 |
| 首异位置 **== 抢占点**（污染特征） | **0** | **0** | 应为 0 → **未出现** |
| 首异位置**早于**抢占点 | 2 | 0 | 抢占前已因批组成噪声分歧，无法评价重算 |
| 首异位置**晚于**抢占点 | 5 | 5 | 重入后一段 token 与对照一致 → 重算正确 |

即能给出肯定结论的条数：**V1 6/8、main 9/9**，且无一条落在"污染特征"上。

### 2. 重入走的是"整段重算"，不是"前缀命中续算"

这是本次最意外的发现。两分支合计 19 次抢占重入的续算点：

| 分支 | 输出 | 重入后 nc/nt | 重算 token 数 |
| :--- | :--- | :--- | ---: |
| V1 | 7 次 | **0**/768 ~ 0/1025 | **768 ~ 1025** |
| V1 | 1 次 | 512/1025 | 513 |
| V1 | 1 次 | 512/769 | 257 |
| main | 9 次 | **0**/769 ~ 0/1025 | **769 ~ 1025** |
| main | 1 次 | 512/1025 | 513 |

**整段重算（`num_cached_blocks = 0`）占 V1 7/9、main 9/10。** 根因：被抢占时刚刚写入的块，在重入时前缀哈希已失效——块被其他 seq 复用后 `token_ids` 被 reset，`can_allocate` 正确判定为不匹配而 break。所以 P4 实际覆盖的是**触及面更广的整段重算**路径，而**不是**原先预期要验的"从前缀缓存处续算"：后者两分支合计只出现 3/19 次（V1 2/9、main 1/10）。这是本节最重要的**覆盖盲区**披露——整段重算出错会大面积崩坏、更易被抓到，续算出错只影响少数 token、更隐蔽。

### 3. 噪声地板必须实测：跨运行比较不存在"bf16 之内"

同配置重跑（对照 vs 对照重跑）：**token 完全一致，logits max|Δ| = 0.000000**（12384 点全 0）→ 采集管线无随机源。

但只要**解码批行数变化**（24 行 vs 23 行），就产生：

| 分支 | 对照 | 比较点数 | top1 一致 | top-20 交集 | **max 相对 Δlogit** |
| :--- | :--- | ---: | ---: | ---: | ---: |
| V1 | 低压力（N=16 vs N=15） | 1725 | 99.8% | 19.7/20 | **3.16e-2** |
| V1 | 高压力（N=24 vs N=23） | 11267 | 100.0% | 19.9/20 | **5.88e-2** |
| main | 高压力（N=24 vs N=23） | 10864 | 100.0% | 19.9/20 | **5.10e-2** |

bf16 表示精度是 2⁻⁸ ≈ 3.9e-3，噪声地板是它的 **8~15 倍**。所以"Δlogit 落在 bf16 精度内"这个判据在**跨运行**比较里根本不可能成立（A1 的教训在更换批组成时量级更大）。判据只能是"**与实测噪声地板同量级**"。

**地板必须按分支实测，不能跨分支复用。** 同为“24 行 → 23 行”，V1 是 5.88e-2、main 是 5.10e-2。地板取的是全批全位置的**最坏点**，随批组成演化轨迹变化，属混沌量、无法从第一性原理推算。早期版本拿 V1 的 5.88e-2 去判 main 的实验组，得到偏乐观的 **0.97×**；用 main 自己的 5.10e-2 才是正确的 **1.12×**。结论方向不变（均与地板同量级），但流程上这一步不该省。

实验组 vs 对照组（分母均为**同分支**的 N=24 vs N=23 地板）：

| 分支 | 场景 | 比较点数 | top1 一致 | top-20 交集 | max 相对 Δ | vs 地板 |
| :--- | :--- | ---: | ---: | ---: | ---: | ---: |
| V1 | N=16 抢占 | 2003 | 99.8% | 19.7/20 | 2.83e-2 | **0.90×** |
| V1 | N=24 抢占 | 4789 | 99.8% | 19.7/20 | 7.28e-2 | **1.24×** |
| main | N=24 抢占 | 9047 | 100.0% | 19.8/20 | 5.70e-2 | **1.12×** |
| V1 vs main | 均无抢占（基准） | 4339 | 100.0% | 19.7/20 | 5.29e-2 | — |
| V1 vs main | 均抢占（同池 72） | 8350 | 100.0% | 19.9/20 | 5.53e-2 | — |

跨实现两行的比值 = 5.53e-2 / 5.29e-2 = **1.05×**：抢占在同一实现内的差异，与“两实现同负载下的固有差异”同量级。

## 三个踩过的坑（写进判据的前提）

1. **不能用"rank 对齐"比较 top-5 值。** 两次运行的 top-5 集合只要错位，按秩比较就会放大成 25% 的假差异。必须**按 token id 求交**后再比数值。
2. **缩小 KV 池必须保证 `强制池 ≥ admit 所需块数`。** 否则 admit 组成变化 → **prefill 批组成也跟着变** → 抢占前的 ci=0 logits 就不一致，噪声淹没信号。第一次尝试（池 20 vs 163）正是栽在这里，误报"首异位置 = 抢占点"。
3. **`torch.argmax` 与 `topk` 在平局时 tie-break 不一致**（12384 点里 50 点，`top1==top2` 的点有 98 个）。所以"top-1 索引是否相同"不是干净指标，只有 **token 序列**（`div`）和**按 id 求交的 logits 差**可信。

## 设计要点（复现须知）

- **唯一自变量 = KV 池块数**：`--force-delta` 把池定为 `max(admit_need, 自然池 − delta)`。两次运行注入方式、prompt、budget 全同，**prefill 批组成完全一致**，差异只出现在 decode 阶段。
- **对照不能"逐条串行跑"**：批组成全盘不同，噪声会盖过信号（实测 4 条 seq 里 1 条首 token 就翻）。
- 只用 `ModelRunner.run` / `Scheduler.preempt` / `BlockManager.{can_append,can_allocate}` / `Scheduler.__init__` / `Sampler.forward` 五处 monkey-patch，不动仓库源码；两分支通用（main 的 `run` 返回 `token_ids`，V1 返回 `(token_ids, need_logits)`，采集端做兼容）。

## 复现

```bash
B="--n 24 --plen 768 --o-base 240 --o-step 24"
python experiments/a_preempt.py --tag V1b_ctl  $B --out experiments/results/a4_V1b_ctl.json
python experiments/a_preempt.py --tag V1b_ctl2 $B --out experiments/results/a4_V1b_ctl2.json
python experiments/a_preempt.py --tag V1b_n23  --n 23 --plen 768 --o-base 240 --o-step 24 \
    --out experiments/results/a4_V1b_n23.json
python experiments/a_preempt.py --tag V1b_px   $B --force-delta 91 --out experiments/results/a4_V1b_px.json
python experiments/a4_compare.py experiments/results/a4_V1b_px.json experiments/results/a4_V1b_ctl.json \
    --repeat experiments/results/a4_V1b_ctl2.json --noise experiments/results/a4_V1b_n23.json
```


## 遗留

- main 侧未跑 `ctl2`（重跑自检）：确定性沿用 V1 结论（同一 `Sampler.forward` argmax 补丁，与调度实现无关）。若要完全自洽，补一条 `mainb_ctl2` 即可（约 35 s）。
- 只覆盖到 9~10 次抢占。若要更好的统计，可提高压力（更小的相对池、更多块边界穿越）后重跑。
- 抢占期间**没有出现 OOM / 断言失败 / 死锁**，但这只是 8G 卡 + 0.6B 的场景结论。
