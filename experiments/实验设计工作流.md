# 实验设计工作流

> 沉淀于 2026-10-14，复盘 B 组（目的达成）设计连续三次失败之后。
> 这不是通用实验方法论，而是**从本项目的具体踩坑反推出来的门禁流程**——每条规则后面都挂着一个真实代价。

---

## 0. 为什么要这个流程

B 组旧设计跑了 6 个 run × 2 次重复，结论是「无收益」。
真因是**被验证的机制根本没有激活**（budget=16384 > prompt≈4700 → chunked prefill 恒不分块，V1 也一步吃完整条 prompt）。

浪费的不是算力，是**结论的可信度**：
> 一次「机制未激活」被当成「机制无效」报告，等价于凭空造了一个假阴性结论。后续所有建立在它之上的推理都是错的。

更值得反思的是：`实验方案v2.md` §B1「为什么默认 bench 负载测不出」和 §B4「陷阱」**当时就写了这个坑**。
知道陷阱 ≠ 流程里有门禁。**教训不是"想得不够细"，而是"没有在下游花钱之前强制验证上游假设"。**

---

## 1. 核心命题：三种失败必须可区分

一次对照实验只有三种结局，而**旧 B 组把第 1 种当第 2 种报了**：

| 状态 | 含义 | 该说的话 |
| :--- | :--- | :--- |
| **① 机制未激活** | 干预根本没被走到（配置没落进触发区） | 「本次设置下 chunked 未生效，实验无效，需重设」 |
| **② 机制激活但无效** | 真结论：优化在这条负载上没收益 | 「chunked 已生效（混合步 N 个），但 ITL 无改善」 |
| **③ 机制激活有效** | 有收益，接下来量化收益与代价 | 「chunked 已生效，ITL max 降至 1/20，代价是空洞频率 ×2.6」 |

**整个流程的唯一目的**：在花大钱跑正式实验之前，用四道门禁证明「系统不在状态 ①」，即干预真的被走到了。

> 判据不只是"测什么"，而是"**没测出差异时，我能否排除'它没生效'**"。任何不能排除 ① 的判据设计，都是不可用的。

## 2. 四道门禁

四道门**全部在冒烟运行之前**完成纸面推演；冒烟运行负责把它们逐一变成"实测为真的活判据"。

### 门 1 · 激活门（Activation）

**问题**：我干预的那条代码路径，在什么条件下才会被执行？

**动作**：读实现，找出干预分支的触发条件，写成对**配置 / 负载**的不等式；再指定一个**可观测量**作为活证据。

| | 本例（chunked prefill） |
| :--- | :--- |
| 触发条件（纸面） | `max_num_batched_tokens < prompt_tokens` |
| 旧设置代入 | 16384 < 4700 → **恒假**，机制从未激活 |
| 归因检查 | 旧结论「无收益」无法排除状态 ① → 结论作废 |
| 可观测量（活证据） | 单条 seq 的 chunk 数 > 1；混合步数 > 0 |
| 阈值 | chunk 数 ≥ 2（本例长 prompt / 1024 ≈ 4~5） |

**反例（当时差点走错）**：以为「调大 `max_model_len` 造更长的 prompt」也行。
实际 `allocate_kv_cache` 公式里没有 `max_model_len`（实测 4096/8192/16384/32768 → 池恒定 163 块），长 prompt 只让**并发掉下去**（4700→19 块/条、10000→40 块/条），不改变激活条件。→ **认准唯一自变量，别用间接量替代。**

**通过条件**：不等式成立 **且** 冒烟里可观测量达到阈值。

---

### 门 2 · 对称门（Symmetry）

**核心命题**：**控制变量 = 控制行为，不是控制参数。**
两版实现不同，**同名参数的语义可能不同**。

**动作**：列出所有同名 / 同类参数，逐个问「它在 A 版和 B 版的实际行为是否一致？」。不一致 → 换成两版**语义相同**的约束量。

| 参数 | V1 语义 | main 语义 | 判定 |
| :--- | :--- | :--- | :--- |
| `max_num_seqs` | running 段与 waiting 段**共享**同一计数 → resident 恒被压在 N | `schedule()` 每步从零计数 admit waiting → waiting 非空时 resident 涨到**池满**（实测 ~32 条 vs V1 8 条） | ✗ 同名不同义 |
| `ModelRunner.run(seqs, x)` | `x` = `is_uniform`，**True = decode** | `x` = `is_prefill`，**True = prefill** | ✗ 语义相反 |

**解法**：改用两版语义**相同**的量来约束 —— 本例改用**池控**（池 = 前 N 条负载的块数之和，且每条总长恒定使块数不变）。
池是物理量，两版都必须遵守，语义天然一致。

**对称性判据（必须实测）**：两版**抢占次数均为 0** **且** 两版**峰值并发接近**。任一不成立 → 回门 2 重设。

---

### 门 3 · 容量门（Capacity）

**动作**：用**峰值**（不是均值）算并发 / 池的可行域，留安全裕度；**先算不等式，跑后必须实测计数为 0**。

**本例不等式**（抢占 = 0 的保证）：

```
floor(池 / 块数_peak) × (块数_peak + 1) ≤ 池
块数_peak = ceil((P_max + O_max) / block_size)     # block_size = 256
```

**两个坑**：

1. **用均值估池**。旧 §B2 按均值 13 块/条算，实际峰值 `P=4096+O=256 → 17 块/条` → 实测 V1 抢占 2 次、main 4 次。
2. **漏算 decode 期的块增长**。块数不是 prefill 时那么大就完了 —— decode 每跨一次 256 边界要**追加一块**。`+1` 项就是它。

**通过条件**：实测抢占 = 0（或按设计非 0），且两版一致。

---

### 门 4 · 判据门（Criterion）

**动作**：按顺序走三步，**顺序不能反**：
1. 先写**预期失效模式**（"如果优化生效，哪个指标会动、往哪个方向、大概多少量级"）
2. 再选判据
3. **阈值必须先在数据分布上标定**，不许凭空定

**本例反例**：空洞占比判据取「`ITL > 3 × p50`」。
p50 ≈ 25 ms → 阈值 75 ms，恰好卡在 **V1 混合步 78 ms 刚过、main 停顿全部 ≥ 300 ms** 的位置。
该指标实际度量的是**抖动频率**，却被当成"最坏情况"的判据，**给出与尾部量完全相反的结论**（V1 空洞更多，但 V1 的最坏情况好 20 倍）。

**规则**：
- **尾部量（CV / p99 / p50 / max）与频率量（空洞占比）必须并列报告**，单独任一个都能误导。
- 判据分层（数值 → 分布 → 语义 → 任务），选「**能覆盖目标失效模式的最弱判据**」。别用最强判据去证最窄的命题（= 浪费），也别用最弱判据去证最宽命题（= 漏检）。

**通过条件**：每个判据都能回答"若机制生效，它的读数会怎么变"。

## 3. 采集三纪律

过了四道门才开始放量，放量期间守三条纪律。

### 纪律 1 · 冒烟先于放量

小规模、单场景、短时长。**只看结构量**（步类型构成、抢占计数、chunk 数、峰值并发），**不看性能数字**。

> 旧 B 组拿一个完整的 6 run × 2 重复批次当冒烟用。代价不是多花了几十分钟，是**等了一整批才拿到"机制没激活"这条信息**——而这条信息在第一个 run 的前 100 步内就已确定。

**产出**：一份"结构量实测值 vs 门 1/2/3 预期值"的比对，全绿才放量。

### 纪律 2 · 噪声先于效应

**先测噪声地板，再谈效应量。** 而且噪声必须**跨会话**测（重启进程重新加载模型），不是同进程重复。

| 测法 | 读数 | 结论 |
| :--- | :--- | :--- |
| 同进程 3 次重复 | std ≈ **0.5%** | **假精度** |
| 跨会话漂移 | **2.7%（V1）/ 5.2%（main）** | 真实可比性上限 |
| 交替配对（A,B,A,B 相邻运行，3 对） | 0.986 / 0.982 / 1.003 | 可用 |

**规则**：效应量 / 漂移 < 2 → 只能报「**无稳定差异**」，或改用**交替配对**抵消会话漂移。**绝不用同进程重复的 std 当误差棒去宣称显著性。**

> 本次正是靠交替配对才发现前两批（同进程重复）方向完全相反。

### 纪律 3 · 归因先于结论

现象要有**机制级解释**才能写进结论。用**结构量**（步数、token 构成、重算量）把效应拆开。

> 本例吞吐 0.991× 的解释靠"三力表"：① V1 混合步整批回退 eager → 7,854 个 decode token（占 decode 5.88%）走 eager；② V1 步数少 199；③ V1 抢占重算多 4,164 prefill token。**三个方向相反的 ±1.5% 力互相抵消** → 净值落进噪声。

**与外部参考数据分歧时，先查基线差异，再谈结论差异。**
> 例：公开数据 P999 步延迟 −36.1%，我们 +6~29%。根因不是策略不同，而是**基线不同**——他们的基线 main 不做 chunk 切分（prefill 步是整条 prompt），我们的 main 同样受 budget 约束、prefill 已被切成 1024，V1 的混合步还叠了 decode → 单步更长。**同一策略在不同基线上，收益落在不同指标上。**

## 7. 实例归档：B4 的两个口径质疑（2026-10-14）

> 追问原文：「为什么 B 组实验前提需要不允许抢占呢？只要两边抢占发生的次数差不多不就可以了吗？……第二点为什么这里还需要使用贪心采样，由于我的优化引入了跳过采样的机制，所以正常采样也是观测效果的一部分吧？」
>
> 两问指向同一件事：**被锁掉的到底是「噪声」还是「效应」**。答案是：一个是**结果指标不能当前提**，一个是**patch 的位置根本不在优化路径上**。

### 7.1 「抢占次数差不多就行」——不行，它是结果不是条件

**逻辑错位**：`max_num_seqs`、池大小是**你能设定的**；抢占次数是**跑完才知道的**。拿"跑完才知道的量"当设计前提，等于没有设计。

**而且它在两版语义不同**（正是门 2 的原始案例）：同一个 `max_num_seqs=8`，V1 的 running 受它约束（恒 ≤ 8 条），main 的 resident **完全不受约束**（实测涨到 ~32 条）。

| 配置 | V1 抢占 | main 抢占 | V1 并发 | main 并发 | 结论 |
| :--- | ---: | ---: | ---: | ---: | :--- |
| `max_num_seqs=8`（用同名参数约束） | 0 | **12 / 2 / 7** | 8 | **~32** | ❌ 不对称 |
| 放开 `max_num_seqs`，改由**池**约束 | 0 | **0** | 7.6 | 7.5 | ✅ 对称 |

**关键**：0 抢占**不是额外施加的限制**，而是"两版受同一约束"之后的**自然结果**。实测（`b4p_*`：池 163、负载含块增长、`max_num_seqs` 放开）：

```
V1    preempt=0   conc=7.46/8   prefill_tok=454222  decode_tok=15517
main  preempt=0   conc=7.40/8   prefill_tok=454222  decode_tok=15517   ← 工作量逐位相同
```

**反过来才是要害**：若两版抢占次数不同，恰恰说明**约束不对称** —— 此时测到的一切差异都无法归因到"chunked prefill"，因为同时改了并发与工作量。

**为什么它不能"算进效果"**：抢占触发**整段重算**（A4 实测：重入时前缀哈希失效 → 重算 768~1025 token），一次抢占 ≈ 20~40 个 decode 步的成本。两版抢占次数不同 → **总 prefill token 数不同** → 吞吐与 ITL 全部失去可比性。

> "算进效果"的正确做法是另设一个**允许一切发生的综合口径** —— 即 C0 标准 benchmark（256 并发、池超订、抢占发生），结论 **0.991×（无稳定差异）**。机制归因（B 组）与综合效果（C0）互补，不是二选一。

### 7.2 「patch 采样会掩盖跳过采样机制」——不会，patch 不在那条路径上

**代码位置**（决定性证据）：

```python
# nanovllm/layers/embed_head.py —— V1 的「跳过」发生在这里
last_indices = context.cu_seqlens_q[1:] - 1
last_indices = last_indices[context.need_logits]   # ← 先筛掉不需要的 seq
x = x[last_indices].contiguous()
logits = F.linear(x, self.weight)                  # ← lm_head 因此少算这几行

# nanovllm/layers/sampler.py —— patch 打在这里
def forward(self, logits, temperatures):           # ← 被替换的是这个
```

patch 在 **lm_head 之后**，筛选在 **lm_head 之前**，两者不相交。

**实测印证**：记录每步 lm_head 的实际行数，两种采样模式下**逐位相同**：

| tag | sampler | lm_rows | 步数 | wall_s | ITL p50 | ITL p99 |
| :--- | :--- | ---: | ---: | ---: | ---: | ---: |
| V1 | argmax | **15491** | 2077 | 74.7 | 25.1 | 92.3 |
| V1 | normal | **15491** | 2077 | 75.3 | 25.2 | 93.0 |
| main | argmax | **15875** | 2472 | 74.9 | 24.7 | 308.4 |
| main | normal | **15875** | 2472 | 75.4 | 24.9 | 308.7 |

行数与步数**完全不变** → 采样模式**根本没触碰**跳过机制。

**patch 实际改了什么**：只把每行 logits 的**后处理内核**从 `softmax + Gumbel-max` 换成 `argmax`。实测代价：墙钟 **0.6~0.9%**、ITL p50/p99 **<1%**，且两版方向一致（`main ÷ V1` 的 ITL max 在两种模式下都是 10~20×）。

**顺带量化了该优化**：`main − V1 = 384 行`，正是 main 在 **384 个 prefill 中间步**做的无用 lm_head（480 个纯 prefill 步 − 96 个「最后一块」），V1 全部跳过。

> 但 384 行的时间代价极小：单行 lm_head ≈ 0.07 ms → 合计 **≈27 ms，占 75 s 的 0.04%**。
> 所以 **need_logits 跳过是正确的工程实践，却不是 B 组收益的来源** —— 收益（ITL max 降至 1/20）来自相位分离的消除。patch 既没掩盖它，也没夸大它。

### 7.3 两条通则

1. **能被设定的量才能当条件，观测出来的量只能当判据。** 「抢占次数差不多」是判据；「池多大、`max_num_seqs` 多大」才是条件。
2. **判断一个 patch 是否掩盖效应，别靠推理，去数它前面的量。** 记下每步 lm_head 的行数——行数不变，就是没碰到。
