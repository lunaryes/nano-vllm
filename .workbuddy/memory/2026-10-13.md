## B 组实验（目的达成）完成 —— 结论：部分达成

新增脚本 `experiments/b_smooth.py`（采集）/ `b_compare.py`（比对），三个场景 × 两分支 = 6 次运行，全部 preempt=0。

### 关键结论
- **base（budget=16384）：无收益**。V1 CV 1.607 vs main 1.589（略差）。机制：V1 混合步 mean **315.9ms** ≈ main「纯 prefill 步 283.0 + 后续 decode 步 23.9 = **306.9ms**」→ V1 只是把停顿搬进同一步。budget ≥ prompt 时 V1 的 chunk = 整条 prompt，比值≈1，必然无收益。
- **s2（同 budget、O 缩小）：负面对照，仍持平**（CV 1.69 vs 1.70）。两版同步恶化（p90 26→293ms）→ **驱动力是 chunk 大小（budget），不是 prefill/decode 比**。
- **s3（budget=2048）：收益出现，但形态是「换尾」**。V1 CV 0.903 vs main 2.241；p99/p50 6.17 vs 12.50；max **162ms vs 2285ms**。但空洞占比 **10.94% vs 4.82%（更差）**，p90 78ms vs 26ms。per-3-chunk 窗口：V1 ITL=(117,117,117)，main=(303,24,24)，**总时长相同**。
- **规律**：V1 最坏 ITL ≈ `T_prefill(chunk) + T_decode`；main ≈ `T_prefill(积压整条 prompt) + T_decode`。收益比 ≈ chunk/prompt。
- **TTFT**：p50 增幅 +0.4%/+2.0%/+0.8% → 达成（≪10%）。**利用率**：混合步 87/85/276 vs main 恒 0 → 达成。**吞吐**：0.99×/0.98×/1.00× → 无收益。

### 两个重要踩坑/修正
1. **抢占=0 的硬条件**：`floor(池/prompt块数) × (prompt块数+1) ≤ 池`。方案 §B2 用**均值**估池（13 块/条）漏了**峰值**（P=4096+O=256 → 17 块/条）→ 原负载 P~U[2048,4096] 实测 V1 抢占 2、main 抢占 4。改成 **P~U[4609,4864]（固定 19 块）+ max_num_seqs=8** → 两版并发都是 8、对称、抢占 0。
2. **§B3 的「空洞计数（ITL>3×p50）」在本实验失效**：阈值 75ms 恰好卡在 V1 混合步（78ms）刚过处，而 main 的停顿全部 ≥300ms。该指标衡量**抖动频率**不是**最坏情况**，与尾部结论相反。→ 必须尾部量（CV/p99/p50/max）与频率量并列报告。

### 新增脚本
- `experiments/b_bench.py` —— 标准吞吐采集，口径**对齐仓库根 `bench.py`**（两分支逐字节相同）：n=256 / P~U[100,1024] / O~U[100,1024] / max_model_len=4096 / budget=16384 / max_num_seqs=512 / temp=0.6 / **不 patch 采样**，另记抢占计数 + 步级 (dt, np, nd) + TTFT/ITL 分位。支持 `--repeat`（同进程多轮）。
- `experiments/b_bench_compare.py` —— 生成 `results/b_compare_bench.md`。

### 关键结论
- **官方口径下吞吐无稳定差异**：V1/main wall = 0.968（3 次重复批）/ 1.047（单次 raw 批）—— **两批方向完全相反**；交替配对 3 对 = 0.986 / 0.982 / 1.003，均值 **0.991**。
- **结构层面确定的三个力**（方向相反、各约 ±1.5%）：① V1 混合步整批回退 eager → **7,854 个 decode token（占 decode 5.88%）走 eager，main 为 0**；② V1 步数少 199（3,996 vs 4,195）；③ V1 抢占重算多 4,164 prefill token（71,743 vs 67,579）。三者抵消 → 净值落在噪声内。
- **口径警告**：池 163 块对 256 seq 严重超订，**重算占 prefill 的 1/3**，端到端由「排队+抢占重算」主导 → 测的是真实压力吞吐，不是稳态吞吐。
- **s3 三次重复**：步数逐次完全一致（V1 1992 = P3/D1713/M276；main 2232 = P288/D1944/M0），抢占 0。V1 max 160~166ms、main max 2217~2285ms（约 14× 差距，远超各自散布）→ B3 结论可复现。

### 方法论沉淀（重要，可复用）
- **同进程 3 次重复的 std 仅 ~0.5%，但跨会话漂移达 2.7%（V1）/ 5.2%（main）** → 单批重复会给出**假精度**。凡跨分支比较，必须用**交替配对**（V1,main,V1,main…相邻运行）抵消会话漂移。本次正是靠配对批才发现前两批方向相反。
- 另一观察：**V1 墙钟比 main 稳得多**（配对三次 98.85~98.94s，0.1%；main 95.4~100.7s）。步数/抢占/token 逐次相同 → 差异纯环境（GPU 时钟/占用），不是调度。
